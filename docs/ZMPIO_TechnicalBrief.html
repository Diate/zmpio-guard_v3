Technical Brief · Embedded SoC

ZMPIO Guard V3

A vibration-monitoring system built across every layer of a Xilinx Zynq-7020: a DSP pipeline synthesized into FPGA fabric, a FreeRTOS application owning the sensors and the memory card, and embedded Linux consuming a feature stream — three domains on one chip, meeting only in shared DDR.

  • Zynq-7020
  • Cortex-A9 ×2
  • FreeRTOS + PetaLinux 2023.2
  • Verilog + Vitis HLS
  • MIT
Source github.com/Diate/zmpio-guard_v3

What the system does

01

An MPU6050 accelerometer is sampled at 100 Hz on three axes. That stream is filtered, reduced to a scalar, transformed, and compressed into a 10-element feature frame roughly every 640 ms — a 64:1 data reduction that keeps what anomaly detection needs and discards the rest. Feature frames are checked against versioned threshold rules, written to a microSD card in a self-describing log container, and simultaneously streamed to Linux for capture.

The engineering interest is not the algorithm. It is that the three processing domains have genuinely different failure modes — a hung RTOS task, a Linux process killed mid-read, a full FIFO in fabric — and the interfaces between them had to be designed so that each failure is contained, counted, and distinguishable from the others after the fact.

PL integration — Vivado block design & AXI

04

The HLS core doesn't reach the processing system on its own. It's packaged as an IP-XACT component and wired into a Vivado block design through three hand-written AXI4-Lite peripherals, so custom RTL sits on the bus exactly like a vendor IP block.

Ethernet connectivity

05

CPU0 reaches the board's RTL8201F 10/100 PHY through Zynq GEM0 and an EMIO-to-MII path in programmable logic. A dedicated bare-metal image using the lwIP RAW API validates the complete MAC-to-network path independently of the main PetaLinux runtime.

On-board testing confirmed link negotiation, DHCP addressing, DNS resolution and ICMP connectivity to a public Internet host. The bring-up sequence below captures the acceptance path without exposing pin-level configuration or UART logs.

Cross-core IPC

06

Two Cortex-A9 cores running different operating systems share a ring in uncached DDR with no lock and no hardware mailbox. Correctness rests entirely on write ordering and on a single-producer, single-consumer discipline that the design enforces rather than assumes.

Engineering decisions

07

One C++ source, two synthesis targets

verifiability

The DSP algorithm compiles on a PC to generate golden vectors and is synthesized by Vitis HLS into the RTL that runs in fabric. Both must agree bit for bit.

Cost: the algorithm may not allocate, may not do I/O, and may not touch <chrono> — every design choice inside it is constrained by HLS synthesizability. Return: the entire signal chain regresses offline with no board attached, and a fabric result that diverges from the host model is a provable defect rather than a judgement call.

Wire layouts are pinned at compile time

interface safety

Every struct crossing a core boundary carries a layout hash, and each field is guarded by an offsetof() _Static_assert in the firmware.

Cost: a deliberate field change means regenerating the hash and re-verifying the affected channel. Return: an accidental field reorder breaks the build loudly instead of producing plausible-looking garbage on a board that is hard to instrument.

The stream path never blocks, it drops and counts

real-time

Feature sends use a bounded wait. When the ring is full the frame is discarded and a counter increments; the task returns to servicing fabric on time.

Cost: the Linux side can miss frames and must reason about gaps. Return: a late result task overflows the 64-deep FIFO in fabric, which is a real hardware failure. A missing frame in a log is not. The design trades the cheap failure for the expensive one.

Sequence numbers are assigned only on a successful send

observability

A dropped frame does not consume a stream sequence number.

Return: a gap in the sequence can then mean exactly one thing — lost in transit after CPU1 sent it — and never "CPU1 failed to send." Two failure modes that would otherwise be indistinguishable in a capture become separable without any extra telemetry.

DSP resources are capped on purpose

area / throughput

An HLS allocation pragma limits the design to one instance of each expensive operator in five places, holding it to 25 of 220 DSP48E1 slices.

Cost: throughput per frame drops substantially. Return: the frame budget is 32,000,000 cycles and a frame needs tens of thousands, so three orders of magnitude of headroom were spent to leave the rest of the device free.

What was demonstrated on hardware

09
  • 10,000 of 10,000 doorbell interrupts delivered with no lost wakeup; spurious interrupts produced no phantom events, and an interrupt storm did not crash the system.
  • 4 of 4 fault-injection gates passed, including resetting the DSP core mid-run and forcing the fabric FIFO full — in both cases the I²C, SD and scheduler paths kept running and the backlog drained.
  • One-hour IPC soak and roughly 25 minutes of continuous feature streaming to Linux with zero drops, zero gaps and zero mount failures.
  • Ethernet to the open Internet on the CPU0 bare-metal image — DHCP bind, DNS resolution and ICMP replies from a public host.
  • Two stack overflows located by direct observation, not inference: halting CPU1 over JTAG put the program counter inside the overflow hook, and reading the task-name bytes at the hook's argument pointer named the offending task.
  • A cross-core interrupt race root-caused: the Linux core's GIC distributor initialization ran after CPU1 had already enabled its interrupt, silently clearing the enable bit. The fix makes CPU1 wait on the distributor control register and re-arm under a watchdog.

By the project's own rule on evidence, V3 is not declared complete. It is released at the level that has been proven, and the gap is documented rather than left for a reader to discover.
